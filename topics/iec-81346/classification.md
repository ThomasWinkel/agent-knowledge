# Classification and letter codes

Standard: IEC 81346-2:2019. The tables are copyrighted: look codes up in the standard, do not copy the tables. Facts from the public preview (clauses 1-4) unless noted.

## Schemes in IEC 81346-2:2019

| Clause | Scheme | Tables | Typical use |
|---|---|---|---|
| 5 | inherent function of objects | 1 entry classes, 2 two levels, 3 all three levels | products/components, also systems ("objects (including systems and system elements)") |
| 6 | spaces | 4 | location aspect (rooms, built spaces) |
| 7 | infrastructure objects | 5, 6 | infrastructure |

- Class by inherent function, independent of the application: the class code stays stable over the life cycle ("a stake is a stake"). So the class belongs to the component type (library symbol), not to its use.
- A class is set by its definition only, not by its name or examples.
- Tables are complete: no "other" class. No fitting sub-class -> use the higher level (sub-class or entry class).
- Code levels: 1 letter = entry class (`K`), 2 letters = sub-class (`KF`), 3 letters = sub-sub-class (`BAA`).
- Codes can also be used alone as a generic type designation, e.g. in specifications.

## Editions and other parts

- 2019 added a third code level and changed classes; not compatible with 2009 (Wikipedia DE; comparison: annex D of the 2019 edition). Old single letters (`K`, `F`, `Q`) from earlier practice stay common.
- 2009 table: `I` and `O` not used (confusion with 1 and 0) (Wikipedia DE).
- Sector parts of the series exist, e.g. ISO/TS 81346-3 (infrastructure), ISO/IEC 81346-10 (power plants), ISO/IEC 81346-20 (vehicles, RDS-VE) (Wikipedia EN).
- Sector- or project-specific letter code tables are allowed if structured like IEC 81346-2 (ISO/TS 81346-3:2012, 4.2). This is the way for own location and function codes.
